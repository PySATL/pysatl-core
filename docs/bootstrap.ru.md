# Bootstrap

[English version](bootstrap.en.md).

## Что это

Bootstrap (бутстреп) — метод оценки изменчивости статистики или оценки параметров
с помощью повторных выборок. На каждой новой выборке выполняется одна и та же
операция с теми же настройками. Распределение полученных значений позволяет,
например, оценить стандартную ошибку выборочного среднего или оценки параметра.

Рассматриваются два режима для одномерной i.i.d. выборки размера `n`:

- **Непараметрический:** для каждого повтора выбрать `n` исходных наблюдений
  с возвращением. Повторы значений сохраняют свой вес: для `[1, 1, 4]`
  вероятности значений `1` и `4` равны `2/3` и `1/3`.
- **Параметрический:** подогнать модель к исходной выборке и генерировать
  по `n` наблюдений из этой модели. Модель генерации фиксируется для всех
  повторов; если исследуется оцениватель, на каждой новой выборке он выполняется заново.

## Что требуется и что предусмотрено архитектурой

| Что нужно Bootstrap | Что есть и что требуется уточнить |
|---|---|
| Подготовка исходной и повторных выборок | RFC предусматривает `Sample.prepare` и защищённый снимок наблюдений. Каждый повтор можно подготавливать независимо. |
| Повторное вычисление статистики | `Statistic.compute(sample)` позволяет применять одну конфигурацию к разным выборкам. `SampleSession` предоставляет зависимости, кэш и диагностику; при использовании сессий каждому повтору нужна своя сессия. |
| Повторное оценивание параметров | Существующая схема estimation с семейством, оценивателем и результатом подгонки подходит для повторного fit. При интеграции нужно согласовать передачу данных из `Sample`, извлечение численных оценок, статуса и подогнанного распределения. |
| Непараметрическая генерация | Достаточно выбирать индексы исходных наблюдений с возвращением. Это точная эмпирическая мера; отдельное построение ECDF не обязательно, а KDE задаёт другой закон генерации. |
| Параметрическая генерация и воспроизводимость | Есть `Distribution.sample` и стратегии генерации. Однако стандартная стратегия создаёт собственный RNG, а UNU.RAN использует общий URNG. Нужен способ передать управляемый генератор и проверить поддержку нужных моделей. |
| Цикл повторов и общий результат | Требуется реализовать в Bootstrap: число повторов, вызов операции, сбор значений и диагностики, сводки и учёт отказов. Эти обязанности не принадлежат статистике или оценивателю. |

**Вывод:** архитектурные роли позволяют встроить Bootstrap без изменения
основной схемы статистик и estimation. Для готовой реализации ещё нужны
управление повторами, согласование входов и результатов модулей и генерация
с управляемым RNG.

Повторная выборка может оказаться вырожденной: например, `[1, 1, 1]`
не позволяет получить невырожденную нормальную модель при оценке обоих параметров.
Нужно сохранять такие отказы и их причины, определить правила продолжения
и явно указывать, если сводка построена только по успешным повторам.
